    14. Weiterführende Themen

    Dieses Dokument hat die Sprache Kotlin und die am häufigsten verwendeten Bibliotheken für das Schreiben von Schichtenanwendungen, Netzwerk-Clients und -Servern sowie Webservices auf der Java Virtual Machine vorgestellt. Im Folgenden die wichtigsten Themen, die darauf aufbauen.

    14.1. Verarbeitung von XML-Dokumenten

    JSON hat XML beim Datenaustausch weitgehend abgelöst, doch XML wird weiterhin verwendet (Konfigurationsdateien, Dokumentformate, bestehende SOAP-Services). Kotlin nutzt direkt die XML-API des JDK im Paket [javax.xml]:

    • DOM ([DocumentBuilder], [Document], [Element]): Das Dokument wird als Baum in den Speicher geladen, der dann durchlaufen und verändert wird;
    • StAX ([XMLStreamReader], [XMLStreamWriter]): Das Dokument wird fortlaufend gelesen oder geschrieben, ohne vollständig in den Speicher geladen zu werden;
    • XPath ([javax.xml.xpath]), um ein Dokument abzufragen, und XSLT ([javax.xml.transform]), um es zu transformieren.

    Neben dem JDK kann Jackson mit seinem Modul [jackson-dataformat-xml] XML lesen und schreiben, ebenso wie JSON (Kapitel 5), und auch die Bibliothek kotlinx.serialization von JetBrains, die den Serialisierungscode zur Kompilierzeit erzeugt, unterstützt von der Community entwickelte XML-Formate.

    14.2. Webanwendungen

    Kapitel 13 behandelt nur Webservices (Anwendungen, die Daten erzeugen). Für Webanwendungen, die HTML-Seiten erzeugen, oder für andere Möglichkeiten, Webservices in Kotlin zu schreiben, stehen folgende Optionen zur Verfügung:

    • Spring MVC mit einer Template-Engine wie Thymeleaf: serverseitig erzeugte Seiten. Spring unterstützt Kotlin ebenso wie Java (Data-Klassen, Coroutines in Controllern, Kotlin für die Routenkonfiguration); der Autor hat den Kurs „Schritt-für-Schritt-Einführung in das Web-Framework Spring“ (September 2026) geschrieben;
    • Ktor, das Web-Framework von JetBrains, in und für Kotlin geschrieben: HTTP-Server und -Clients auf Basis der Coroutines aus Kapitel 9, konfiguriert mit Kotlin-Code statt mit Annotationen;
    • weitere JVM-Frameworks mit Kotlin-Unterstützung: Quarkus, Micronaut, Javalin und die Jakarta-Anwendungsserver EE;
    • in JavaScript geschriebene Oberflächen (Vue.js, Angular, React), die Kotlin-Webservices nutzen; der Autor hat den Kurs „Schritt-für-Schritt-Einführung in das Framework Vue.js“ (September 2026) geschrieben. Kotlin selbst kann nach JavaScript (Kotlin/JS) oder nach WebAssembly (Kotlin/Wasm) kompiliert werden, wodurch auch die Client-Seite in Kotlin geschrieben werden kann.

    14.3. Mobile und Desktop-Anwendungen

    Dieses Dokument behandelt keine grafischen Benutzeroberflächen: Heute werden Verwaltungsanwendungen meist mit Weboberflächen gebaut. Dennoch ist dies ein Bereich, in dem Kotlin weit verbreitet ist:

    • Unter Android ist Kotlin die von Google empfohlene Sprache, und die Benutzeroberfläche wird mit Jetpack Compose aufgebaut, einer deklarativen, vollständig in Kotlin geschriebenen Bibliothek; Coroutines (Kapitel 9) sorgen dafür, dass die Benutzeroberfläche bei Netzwerk- oder Datenbankzugriffen reaktionsfähig bleibt;
    • Compose Multiplatform von JetBrains erweitert Compose, sodass Oberflächen für Desktop (Windows, Linux, macOS), iOS und das Web mit demselben Code geschrieben werden können;
    • Allgemeiner gesagt, erlaubt Kotlin Multiplatform es, Code der Geschäftslogik (zum Beispiel die Schichten [business] und [dao] aus Kapitel 6) gemeinsam zwischen JVM, Android, iOS (über Kotlin/Native, das Maschinencode ohne virtuelle Maschine erzeugt) und dem Web zu nutzen;
    • Auf der JVM bleiben die Java-Bibliotheken Swing und JavaFX auch aus Kotlin heraus nutzbar. Die in den Kapiteln 7 (Ereignis-Listener) und 9 (Rückkehr in den GUI-Thread mit [Dispatchers.Main]) behandelten Konzepte gelten hier unmittelbar.

    14.4. Tests

    Kapitel 6 führt JUnit und [kotlin.test] ein. Diese werden häufig ergänzt durch:

    • Kotest, ein für Kotlin geschriebenes Test-Framework, das mehrere Stile zum Schreiben von Tests und eine umfangreiche Bibliothek von Assertions bietet ([list shouldHaveSize 7]);
    • MockK, die für Kotlin entworfene Bibliothek für „Mocks“ (simulierte Objekte) der Schichten, von denen die getestete Schicht abhängt (finale Klassen, Objekte, Suspend-Funktionen); Mockito bleibt weiterhin nutzbar;
    • kotlinx-coroutines-test, das Tests von Coroutinen-basiertem Code mit einer virtuellen Uhr ausführt: ein [delay(10_000)] läuft sofort durch;
    • Testcontainers, das für die Dauer der Integrationstests eine echte Datenbank (MySQL, PostgreSQL …) in einem Docker-Container startet;
    • die Test-Werkzeuge von Spring Boot ([@SpringBootTest], [MockMvc]), um einen Webservice zu testen, ohne ihn bereitzustellen.

    14.5. Performance

    Ein Kotlin-Programm wird von der Java Virtual Machine (JVM) ausgeführt: Es profitiert von der Just-in-time-Kompilierung und von Laufzeitoptimierungen, mit einer Performance, die der eines Java-Programms entspricht. Zu den Werkzeugen, die noch einen Schritt weitergehen, zählen:

    • das Werkzeug JMH („Java Microbenchmark Harness“), das direkt in Kotlin oder über das Gradle-Plugin kotlinx-benchmark verwendet werden kann, um die Performance von Code präzise zu messen und dabei die Aufwärmphase der virtuellen Maschine zu berücksichtigen;
    • JDK Flight Recorder und JDK Mission Control, die das Verhalten eines Programms in der Produktion aufzeichnen und analysieren; IntelliJ IDEA enthält einen Profiler und einen Coroutinen-Debugger;
    • die Ahead-of-time-Kompilierung in nativen Code mit GraalVM Native Image: eine eigenständige ausführbare Datei, die in wenigen Millisekunden startet, auf Kosten von Einschränkungen bei der Reflection; Spring Boot und Quarkus können solche ausführbaren Dateien aus Kotlin-Code erzeugen;
    • die Wahl des Garbage Collectors (standardmäßig G1, ZGC für sehr kurze Pausen bei großem Arbeitsspeicher).

    14.6. Bereitstellung

    Ein Kotlin-Programm wird genau wie ein Java-Programm bereitgestellt: als [.jar]-Archiv, das von einem auf dem Rechner installierten JDK ausgeführt wird ([java -jar application.jar]), sofern die Standardbibliothek von Kotlin enthalten ist (das tun die von [gradlew installDist] erzeugten Skripte, Kapitel 2; Spring Boot erzeugt eine eigenständige [.jar]-Datei, die alle seine Bibliotheken enthält), als eigenständige Anwendung, die eine auf das Notwendige reduzierte virtuelle Maschine einbettet (die Werkzeuge [jlink] und [jpackage] des JDK) oder in einem Docker-Container (Spring Boot erzeugt direkt ein Container-Image über [gradlew bootBuildImage]).

    • die offizielle Kotlin-Website mit Dokumentation, Tutorials und den Seiten „What’s New“ zu jeder Version: https://kotlinlang.org;
    • die Online-Sandbox Kotlin Playground, um Kotlin-Code im Browser auszuprobieren;
    • die Kotlin Koans genannten Übungen, die auf der Kotlin-Website und in IntelliJ IDEA verfügbar sind;
    • die Vorschläge zur Weiterentwicklung der Sprache (KEEP), um über Neuerungen in kommenden Versionen auf dem Laufenden zu bleiben: https://github.com/Kotlin/KEEP;
    • der Quellcode des Compilers und der Standardbibliothek, verfügbar auf GitHub: https://github.com/JetBrains/kotlin, sowie der Quellcode der Coroutinen: https://github.com/Kotlin/kotlinx.coroutines;
    • die Dokumentation der Java API SE 25 für die aus Kotlin verwendeten JDK-Klassen: https://docs.oracle.com/en/java/javase/25/docs/api/;
    • die Bücher *Kotlin in Action* (Manning) und *Effective Kotlin* von Marcin Moskała sowie, für die Nebenläufigkeit auf der JVM, *Java Concurrency in Practice* von Brian Goetz et al. (Addison-Wesley).
